# 直接交给本地 AI 的任务示例

先把当前仓库文件夹设为工作目录。下面的文件路径、时间点和名称替换成你的真实输入。不要让 AI 凭示例时间猜你的新视频。

## 新增动态陪伴

> 先阅读 README.md、AGENTS.md、docs/MEDIA.md。将我提供的视频新增为动态陪伴，ID 为 my-companion-01，放在 sit 衣橱，名称为“我的陪伴”，循环起点为我指定的 8 秒，循环终点为片尾。不要改现有四套的文件。先核对视频实际时长与参数，使用 project.py 的计划和 apply 流程接入。我还没有对白，先显式关闭这套对白。完成后检查资源与播放，构建本地预览，报告原视频是否保持不变。

## 替换现有样片

> 按 docs/MEDIA.md，将 classic-sample 的视频替换为我提供的文件，定格点为我指定的时间。保留这套 ID 与 hostValue，重新生成封面和推荐定格，清除旧画质引用。对白先保持原文件，明确提醒它仍属于受限示例内容。不要发布或改动其他项目。完成后执行媒体检查和构建。

## 写对白并接入

> 阅读 docs/DIALOGUE.md、docs/PERSONA.md 和目标穿搭的 look.json。根据我提供的角色、穿搭画面和情境，编写两组成对入场接话、10 条持续陪伴、2 条恢复、2 条随机、2 条低频亲昵。语气自然、有互动感，不堆生活流水账。按目标 dialogue.json 格式给每条分配独立 ID；不要改已有批准文本。确认我的修改范围后按现有授权接入，仅改这套对白，执行 check 和 build。

## 调整衣橱

> 按 docs/ARCHITECTURE.md 调整衣橱的名称和默认显示顺序。保留每套 ID、hostValue 和视频内容，不通过改变目录身份来排序。核对每套恰好出现一次、默认款有效，并检查顺序与倒序以及旧收藏恢复。

## 发布自己的作品

> 按 docs/PUBLISH.md 检查这个作品是否仍含模板样片、图片或示例对白，先列出未替换项。全部替换并完成检查后，导出 WE 和 Lively 包到 dist，用新的包名，附清单与本地入口。代码按 0BSD 使用，无需给原作者添加署名、水印或宣传链接；第三方组件遵循各自许可。不复制原作者工坊 ID，不上传、不推送、不改我现用的宿主配置。明确列出实际测试范围和未完成的宿主验收。

## 修改播放器

> 先复现我描述的具体问题，记录触发动作、视频类型、画质和布局，再修改 src/player 中最小必要范围。保留两路视频、取消令牌、手动／系统暂停区分和稳定 ID。添加能复现该问题的检查，不为了通过测试改变预期。完成后说明实际变化及回归结果。
